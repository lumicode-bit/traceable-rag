## 三条 bullet（直接粘）

1. 为 3 份共 163 页的设备手册构建可溯源问答系统：BM25 + bge-m3 向量混合检索（RRF 融合 + 型号强匹配），块级 Recall@5 由 0.854 提升至 0.979，冷查询约 350ms。
2. 设计「片段唯一来源 + 两级引用核验」的生成链路（SSE 流式，DeepSeek）：91 条引用全部可回溯、0 条编造；151 条可判定结论经数值/型号二次校验确认出自引用块；无答案问题 11/11 拒答而非编造。
3. 用纯 HTTP 模型接入 + SQLite 单文件把本地依赖压到 13 个包 420MB（无 torch/PostgreSQL），配 93 个自动化测试与 nginx/HTTPS 部署手册，他人 10 分钟可跑通。

## 填报注意

- **别把 100% 写成「引用准确率 100%」单独出现**。它成立的前提写在括号里：48 条可答题、91 个引用、0 条不存在。面试官追问「样本多大」时，答「48 条，同一批文档，所以只敢说这批 0 幻觉」比硬撑可信。
- **冷/热耗时别混**：约 350ms 是冷查询（每次新问题都要付一次 embedding 往返），5~7ms 是命中缓存。写 5ms 会被一眼看穿。
- **耗时别写成精确值**：远端接口多轮运行见过 325 / 370 / 475ms，写「约 350ms」比写单个精确值稳。
- **「提升 10%」这种表述不要用**。0.854 → 0.979 是 48 条里多对 6 条，说「块级 Recall@5 由 0.854 提升至 0.979」即可，别换算成百分比。
- **「47/48 全部作答」可以说，但要带上那 1 题是什么**：q018（DB9 接口急停接哪个 DI 端子），
  金标块排 top-1，但接线图被压平成管道符，模型不敢用。这句话指向具体技术边界，
  比「1 到 3 题之间波动」强得多，也别写成「48/48」。
- **别把「波动」当成卖点**。早先那组 45/46/47 是拒答判定写错（全文包含标记）造成的假波动，
  改判后三轮稳定 47——讲这件事时要讲「我怎么发现是测量错的」，而不是「模型不太稳」。
- 如果投的是**检索/后端岗**，把第 1 条放前面；投**算法应用岗**，把第 2 条放前面；投**全栈**，第 3 条放前面。

## 面试时可能被追问的三个点（提前想好）

1. **「你怎么知道引用不是编的？」**
   有个独立脚本把回答里的每个 `[文档名 p.页码]` 拿去和本次检索到的片段比对，对不上就退出码 1。数字来自一次真实运行，明细落盘可复核。
2. **「为什么不用 pgvector？」**
   2 万块 × 1024 维也就 80MB，numpy 全量点积在笔记本上几十毫秒；装 Postgres 在这个量级收益为零，成本是几天环境搭建。超过 5 万块会打印告警提示该换。
3. **「这套东西什么时候会答错？」**
   见 `docs/DESIGN.md` 第四节，四个具体场景：右页错块、跨文档串页、引用真实但结论不成立、表格解析失真。**主动说边界比被问出来强。**
