# 三分钟演示脚本

原则：**先给结论，再给证据，最后主动交代边界。** 全程只用一个浏览器窗口，不切幻灯片。

准备两个窗口：① 站点首页；② 仓库里的 `docs/` 目录（备用，网络挂了就切截图）。

---

## 0. 演示前 10 分钟检查清单

```bash
docker compose ps                      # app、nginx 都是 Up
curl -s https://你的域名/health         # {"db":"ok"}
```

- [ ] 手册已入库：文档页能看到 3 份、状态「已入库」、块数合计 203
- [ ] 问答页随便问一句能出字（**不要用演示时要问的那句**，避免耗掉缓存里的向量也没关系，主要是确认 key 有效）
- [ ] 手机连的是同一个网络，能打开站点
- [ ] 截图兜底：`docs/images/` 下放好问答页、文档页、评测页三张图
- [ ] API 余额够（单次问答约 2k–6k token）

**如果现场断网**：切到截图，话术不变，最后补一句"这条回答是刚才在同样环境下跑出来的"。

## 1. 脚本（按秒）

| 时间 | 操作 | 台词 |
| --- | --- | --- |
| 0:00 | 停在首页，不动 | 「现场最常见的场景：工人手上只有一台手机，和一句『上电就报 Err23』。手册 74 页，他要找的是其中一行处理办法。」 |
| 0:10 | 指向输入框 | 「系统不是让他读手册，而是直接把那一行找出来——并且告诉他这句话出自哪一页。」 |
| 0:15 | 输入 `上电就报 Err23 报警，电机或输出线对地短路怎么处理`，点「提问」 | 「注意，这句话里没有任何手册原文的说法，是工人自己的描述。」 |
| 0:20 | **不说话，让回答流式出现**（约 2–4 秒） | （等第一个字出现后再开口）「回答是一个字一个字出来的，不是等十秒后给一整段。」 |
| 0:28 | 指回答里的 `[CP650空压机一体机手册.pdf p.35]` | 「每条结论后面都跟着来源：文档名 + 页码。这条说的是用绝缘测试仪测电机和输出线的绝缘。」 |
| 0:38 | 指向第二条引用 `p.33` | 「这条更关键——Err23 在另一份手册里的定义是『对地短路故障』，处理办法是更换电缆或电机。两份资料说法不完全一样，它把两条都列出来了，而不是自己挑一个。」 |
| 0:50 | 点第一条引用卡片的「查看原文」 | 「点开就是检索到的那段原文，一字未改。所以『它有没有编』这件事，评委可以当场核对。」 |
| 1:00 | 收起原文，滚动到引用列表 | 「这一次检索了 5 个片段，回答只用了其中 2 个。没用到的片段也列在这里，方便判断它是不是漏看了什么。」 |
| 1:10 | 清空输入框，输入 `CP600-4T22G 的出厂序列号编码规则是什么，第几位代表生产年份`，提问 | 「现在问一个手册里确实没有的问题。」 |
| 1:18 | 等回答 | 「它说的是『资料中未找到相关内容』，并且指出缺的是『序列号编码规则』这一类信息。**不会编。**」 |
| 1:30 | 指向回答下方 | 「这句拒答是硬要求写进提示词的：片段不足就只准说这一句。系统里没有任何『实在不行就猜一个』的兜底。」 |
| 1:40 | 切到「文档」页 | 「文档是页面上传的。上传后后台解析、切块、补索引，状态会自己从『解析中』变成『已入库』。」 |
| 1:50 | 指表格里的「页数 / 块数 / 已向量化」 | 「74 页切成 84 块。这里能看出哪些块还没建向量——没向量的块在检索里等于不存在，所以这个数字要盯着。」 |
| 2:00 | 点「重新解析」其中一个文档（可选，视现场网速） | 「重新解析会重建分块，不会产生重复数据；不想要了就删除，分块和磁盘文件一起删。」 |
| 2:10 | 切到「评测」页 | 「这是评测报告，不是手写的：检索部分用 10 条标注题测 Recall@5，混合检索页码级命中 10/10。」 |
| 2:25 | 指报告里的表格 | 「59 条题库，其中 11 条是手册里确实没有的：48 条可答题里 46 条作答，91 个引用 0 个编的；11 条无答案的题全部拒答。」 |
| 2:40 | 回到首页 | 「技术上就三句话：混合检索（BM25 + 向量 + RRF 融合）、片段唯一来源、引用逐条机械核验。」 |
| 2:50 | 收尾 | 「边界也说清楚：引用真实不等于引用能支撑结论，这一点我们没做语义判定；语料只有 3 份手册，指标样本小。细节在 DESIGN.md 里。」 |

**合计 3 分钟。** 如果只给 90 秒，砍掉 1:40–2:10 的文档页，保留「提问 → 引用 → 拒答 → 评测数字」。

## 2. 大概率会被问到的四个问题

**Q：引用准确率 100%，怎么保证不是刷出来的？**
A：校验脚本是独立的（`tests/check_citations.py`），它把回答里的每个 `[文档名 p.页码]` 拿去和**本次检索到的片段**比对，对不上就判失败、退出码 1。题库 59 条、48 条可评分，都是模型逐块出题、我再人工复核删掉的；数字来自一次真实运行，明细在 `data/eval/p3_citations.json`，可以当场重跑。样本仍然只是同一批手册，所以只敢说「这批 0 幻觉」。

**Q：为什么不用 LangChain / LlamaIndex？**
A：链路只有五步（检索、拼提示词、调模型、流式转发、校验引用），自己写大约 800 行，能说清每一行的行为；引框架反而要多解释一层它的默认行为。真正难的不是编排，是「引用能不能被机械核验」——那一块没有现成组件。

**Q：换一个模型还能用吗？**
A：能。向量、重排、对话都是 OpenAI 兼容的 HTTP 接口，`base_url` 从 `.env` 读。换向量模型要同步改 `EMBED_DIM` 并重建索引（`embed_model` 不一致的块会被自动跳过并告警）。换完必须重跑 `check_citations.py`，因为旧的验收记录就作废了。

**Q：为什么没有登录？**
A：演示用，登录会拖慢评审体验也增加被扫面。补偿是：8000 端口只绑本机、公网只走 nginx、key 只在后端。真要长期公开，加一层 nginx Basic Auth 就行。

## 3. 出故障怎么办

| 现场情况 | 立刻做什么 | 话术 |
| --- | --- | --- |
| 提问后一直没字 | 等 10 秒仍无输出就刷新重问一次 | 「第一次调用在建立连接，换一条再试」 |
| 显示「无法连接后端」 | 切截图 | 「这台机器的服务刚被停了，这是同样环境的运行记录」 |
| 回答变成拒答 | **不要硬解释成 bug**，把它当成功案例 | 「这说明它宁可说没有，也不编——这正是我们要的行为」 |
| 引用页码点开是空表 | 说明表格解析失真 | 「合并单元格的表格转文本会错位，这是已知限制」 |
